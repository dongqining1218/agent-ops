## 2. 验证证据

| 验证项 | 结果 |
|---|---|
| 单元测试 | `python3 -m unittest discover -s tests` → **13/13 通过** |
| 端到端（mock） | 事件排队 → 派单 → 回写 `completed` → 仪表盘可见，耗时 <1s |
| 去重 | 同一 `idempotency_key` 第二次返回 `duplicate: true`，不产生新派工 |
| 无规则事件 | 返回 `recorded`，只落库不派单 |
| 同 subject 串行 | 第二条事件在第一条 leased 期间领不到（204） |
| 失败重试 | 3 次失败后事件转 `failed`；期间每次退避后自动重新可领 |
| 租约回收 | 手动把租约改成过期 → sweeper 回收 → 再次派发 `attempts=2` |
| 结论幂等 | 重复 conclude 返回 `idempotent: true`，不覆盖结论 |
| 待决定 | `need_decision` 进入 `/api/inbox` 与 `/ui/inbox` |
| 页面 | `/` 与 `/ui/inbox` 均 200，健康时只显示数字不打扰 |

## 3. 实施中遇到的真实问题

1. **`codex exec` 在 DSH 沙箱下 EPERM**（`failed to initialize in-process app-server client`）。
   它需要完整本地权限，不是代码问题。
2. **codex 登录态失效**：`refresh token was already used` → 已用 `codex login --device-auth` 重新登录（期间 auth 端点偶发 504，重试即可）。
3. **codex 默认模型不兼容**：`deepseek-v4-flash` 在 ChatGPT 账号下报 400 → 规则里显式 `"model": "gpt-5.6-sol"`，并把 `reasoning` 做成规则字段（`-c model_reasoning_effort`）。
4. **结构化输出 schema 被拒**：OpenAI 严格模式要求 `additionalProperties:false` 时所有属性都在 `required` 里 → schema 改严格，并加 `SchemaTest` 回归。
   这决定了执行器不能写死：于是加了 `worker/executor.py` 分发 + `mock_adapter`，`to.runtime` 一行切换。
   真实运行时 worker 会明确回写「codex 登录失效，请先运行 `codex login`」，不会假装成功。
