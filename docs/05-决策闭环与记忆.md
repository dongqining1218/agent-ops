# 05 · 决策闭环与决策记忆（"批奏折"）

> 目标：把「需要人拍板」这件事做成一条闭环，并让人的决定变成系统的长期资产。
> 对应 03 设计里 A 的「票拟/批红」+「卡兹克定的事」。

## 1. 闭环

```
Agent 干到一半，Report 带 needs_human + human_question
   ↓
/ui/inbox：一张卡片 = 问题 + 它查到的情况 + 同意/拒绝/备注
   ↓  我点一下
decisions 表落库（run_id / 问题 / 选择 / 备注 / 时间）
   ↓
memory/定了的事.md（approve） 或 memory/定了不做的事.md（reject）
   ↓
生成后续事件（带 decision 上下文，idem = decision:<run_id>）→ 中台 → 派给 Agent 继续干
```

## 2. 为什么"决定变成新事件"而不是"改原工单"

- 原工单的结论、执行记录、产物都保留，不被覆盖；
- 后续干活是**一次新的派工**，走同一套规则/排队/回写，审计链完整：
  `原事件 → 决定 → 后续事件 → 后续结论`；
- 想换执行器、换模型、换 skill，只改规则，不用动已发生的记录。

## 3. 决策记忆（长期不被打扰的根本）

| 文件 | 写入条件 | Agent 怎么用 |
|---|---|---|
| `memory/定了的事.md` | 选择不是拒绝类 | 同类问题直接照做，不再上报 |
| `memory/定了不做的事.md` | 选择是 `reject / 拒绝 / no / 不做 …` | 同类问题直接回绝，不再上报 |

条目格式：

```
- 2026-11-13 · run#2 · ticker · 问：要不要删掉这 3 个陈旧分支？ → 定：approve（备注：确认是过期分支）
```

注入方式：每次派活时（`worker/codex_adapter.build_prompt`）把最近 40 条渲染进提示词：

```
## 决策记忆（人已经定过的事，不要重复问）
### 我已经定过的事（遇到同类问题直接照做，不要再问）
- ...
### 我已经拒绝过的事（遇到同类问题直接回绝，不要再问）
- ...
```

> 默认 `.gitignore` 掉 `memory/`（里面是你的原话和判断）。想跨机器共享，把它从 `.gitignore` 删掉再提交即可。

## 4. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/runs/{run_id}/decide` | body：`{"choice": "approve", "note": "...", "decided_by": "me"}`；重复决策/非等待态 → 409，run 不存在 → 404 |
| POST | `/ui/decide` | 表单版（inbox 页用），303 跳回 inbox |
| GET | `/api/decisions?limit=50` | 决策流水 |

## 5. 验证（`python3 -m unittest discover -s tests`，19 项全过）

`scripts/demo.sh` 的实测输出：

```
① 定时敲门 → run #1 completed
② 事件带 question → 收件箱 1 条待决定
③ 同意 → 决定=approve，生成后续事件 #3（queued），写入记忆
④ 带着决定继续干 → run #3 completed：收到决定：approve
⑤ run #1 completed / run #2 decided / run #3 completed
```

## 6. 还没做的

- 卡片自定义选项：`options` 已入库，但 inbox 目前只渲染同意/拒绝/备注（Agent 给的额外选项还不会显示成按钮）；
- 决策的"拒绝并说明原因"还没有回灌给 Agent 做后续调整（现在是拒绝也生成后续事件）；
- 记忆只是提示词注入，还没有做去重/合并（同类问题会积累多条，后续可以按 subject 聚合）。
